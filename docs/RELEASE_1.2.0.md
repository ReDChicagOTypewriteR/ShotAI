# ShotAI 1.2.0 更新说明

## 总体更新

- 公共聊天界面支持通过自然语言自动生成图片和连续修改上一张图片。
- 聊天模型导入改为一次读取：快速检查文件结构，写入过程中同步完成 SHA-256 校验。
- 相同模型文件按内容直接复用，导入中断会保留明确错误并允许清理临时文件。
- 默认服务容量为五位活跃用户：两路同时推理、三路等待，第六路请求不会继续压入显存。
- 当前服务器聊天模型基线为 Qwen3.5；更新说明和测试不再把 DeepSeek-R1 当作正在使用的模型。
- Windows 与 Ubuntu 共享业务核心，但安装器、运行组件、路径、日志与发布目录彼此独立。

## Ubuntu 1.2.0

- 面向 Ubuntu 22.04 x86_64、Tesla V100 和完全离线环境。
- 使用独立 Ollama 端口及模型目录，避免系统 Ollama 污染 ShotAI 模型列表。
- 内置 Ollama 优先使用 CUDA 12，并在监控中显示实际显存、GPU 卸载层和 CPU 回退状态。
- 模型导入可直接写入 ShotAI 独立仓库，减少大文件重复读取和本机二次传输。
- DEB 输出到 `release/ubuntu`，不修改 Windows 发布目录。

## Windows 1.2.0

- 保留 Windows 独立安装器、运行组件、路径和进程管理。
- 完整包继续携带 Windows Ollama CUDA 12 与 Windows 图片运行组件，但不携带模型权重。
- 使用与 Ubuntu 相同的一次读取导入、五人容量控制和对话式图片操作。
- EXE 输出到 `release/windows`，不修改 Ubuntu 发布目录。

## 默认并发策略

| 项目 | 默认值 |
| --- | ---: |
| 活跃用户上限 | 5 |
| 同时推理数 | 2 |
| 等待队列 | 3 |
| 同时加载的聊天模型 | 1 |
| 默认上下文 | 8K |

该限制用于保护显存稳定性，并不表示五条请求会在显卡上完全并行运行。管理员可在数据目录的 `lan.config.json` 中调整 `concurrency`，修改后需要完全退出并重新启动 ShotAI。
