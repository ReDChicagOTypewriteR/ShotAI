# ShotAI 图片创作方案

更新时间：2026-07-31

## 当前结论

图片识别和图片创作是两件不同的事情：

- 图片识别：用户上传图片，模型阅读图片并用文字回答。ShotAI 已经支持。
- 图片创作：用户输入描述，模型返回一张新图片。ShotAI 已经提供试用入口。

ShotAI 同时支持两种图片运行方式：macOS 可以继续使用 Ollama 的试用接口；Windows 使用 stable-diffusion.cpp 独立组件。两种方式共用模型选择、尺寸选择、进度、停止、预览和下载界面。

## 推荐路线

### 已完成：工作台试用版

- 在输入框左侧的“+”菜单中加入“创作图片”。
- 自动查找 `FLUX.2 Klein`、`Z-Image Turbo` 及声明图片生成能力的模型。
- 支持正方形、横图、竖图。
- 显示生成进度，允许停止任务。
- 支持结果预览与保存为 PNG。
- 未找到模型时显示推荐模型和可复制的安装内容。
- 所有浏览器请求继续通过 ShotAI 内网服务转发，不直接连接 Ollama。
- Windows 启动器自动查找 stable-diffusion.cpp 与模型文件，并启动图片服务。
- 支持 FLUX.2 Klein 单文件和主模型、文字理解、图片解码三文件结构。

### 下一阶段

- 把经过验证的 Windows CUDA 运行文件固定到正式版本，提供校验值。
- 增加主机任务队列，限制同一时间只生成一张图片。
- 由主机统一保存生成历史，供内网用户恢复。

## 适合当前测试主机的模型

当前主机为 RTX 4070 Ti、32 GB 内存。首测推荐 `x/flux2-klein:4b`，下载约 5.7 GB：

```shell
ollama pull x/flux2-klein:4b
```

需要更好的中文文字和写实效果时再测试约 13 GB 的 `x/z-image-turbo`。在 Windows 正式支持明确之前，不把它们列入面向普通用户的一键安装清单。

## 开发前必须完成的检查

- [x] 自动判断已安装模型是否可以创作图片。
- [x] 生成任务可以停止，失败后可以重试。
- [x] 通过同源内网服务访问，避免浏览器跨域问题。
- [x] Windows 启动器自动判断图片组件与模型文件是否准备完整。
- [ ] 显存不足时给出专门提示，不让主服务崩溃。
- [ ] 图片生成后由主机统一保存，而不是长期放在浏览器内存中。
- [ ] 多人同时生成时排队，避免显卡内存被同时占满。
