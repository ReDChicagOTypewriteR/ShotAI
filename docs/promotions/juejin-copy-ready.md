# Vue 3 + Electron + Ollama：一台主机如何服务多台浏览器

> 从同源代理、任务模型路由到浏览器本地资料库，记录 ShotAI 1.1.6 的工程实现与边界。

很多本地 AI 工具解决的是“如何在这台电脑上调用模型”。但当场景变成办公室、工作室或家庭，多台电脑分别安装运行时、下载模型、处理配置，很快就会变成重复而难维护的工作。

我做 ShotAI 时，把问题换成了：能不能只在一台 Windows 主机上准备模型，其他电脑打开浏览器就使用？

ShotAI 是一个面向可信局域网的本地 AI 工作台。主机负责模型和计算，局域网内的其他电脑不需要安装 Node.js、Ollama 或模型，只要打开浏览器访问主机地址即可使用对话、文件阅读、资料检索、图片理解和图片创作。

## 一、先把本地模型放到正确的网络边界

当前的请求路径是：

```text
局域网浏览器 → ShotAI:9090
                   ├─ /ollama/ → 127.0.0.1:11434
                   └─ /image/  → 127.0.0.1:1234
```

前端工作台由 Vue 3、TypeScript 和 Element Plus 构建。9090 服务负责提供网页、健康检查，以及 Ollama 和本地图片运行组件的同源代理。浏览器只访问一个地址，主机上的推理服务不需要直接暴露给内网客户端。

这层代理解决了几个实际问题：

1. 客户端不需要知道 Ollama 和图片服务的内部端口；
2. 流式回答可以通过同源服务返回到浏览器；
3. 主机和客户端可以有不同的操作边界；
4. 后续做访问控制、日志和限流时，有一个明确的入口。

默认情况下，主机可以添加、删除和重载模型，内网浏览器主要负责使用。这不是完整的账号权限系统，但比直接把模型接口开放给每台电脑更接近一个可维护的产品边界。

## 二、不让使用者先理解模型，再开始工作

本地 AI 的模型往往按能力拆开：聊天、视觉、Embedding、图片生成分别有不同的运行方式。如果把这些复杂度全部交给使用者，工作台最后会变成一个“模型选择考试”。

ShotAI 尝试按任务做路由：

| 用户动作 | 使用的能力 |
| --- | --- |
| 普通对话 | 聊天模型 |
| 上传 PNG、JPEG 或 WebP | 视觉模型 |
| 查询本地资料 | Embedding 检索；不可用时回退关键词检索 |
| 生成或修改图片 | 独立的本地图片运行组件 |

用户做的是“分析这张图片”或“查一下这份资料”，而不是先研究该切换到哪个模型。

模型管理页负责识别 GGUF、检查文件、处理视觉模型与 `mmproj` 的配对关系，并尽量复用相同的模型文件。

## 三、本地资料库也需要降级路径

资料库是另一个容易被低估的地方。完整的向量检索需要 Embedding 模型，但第一次部署本地 AI 时，用户不一定已经准备好所有模型。

ShotAI 当前会在浏览器中解析 TXT、Markdown、PDF、DOCX 和 Excel 等可提取文本的文件，按约 900 个字符切块，并在相邻片段之间保留一部分重叠内容。

- 有 Embedding 模型时，优先走向量相似度检索；
- Embedding 不可用或查询失败时，退回关键词和中文匹配；
- 回答下方显示命中的文件、片段、匹配方式和摘录；
- 知识库索引默认保存在当前浏览器的 IndexedDB 中。

这里的目标不是替代复杂的企业知识库，而是让第一次部署时少一个硬依赖，同时让使用者能够看到“答案来自哪些资料”。引用是检索过程的展示，不等同于独立事实核验或权限审计。

## 四、浏览器本地状态：轻量，但有明确代价

对话、附件解析结果、资料索引、设置和最近生成记录默认保存在当前浏览器的 IndexedDB。这样做的好处是轻量，也不会默认把每个客户端的历史集中到主机服务器；代价同样明确：

- 不同电脑或不同浏览器之间不会自动同步记录；
- 清理浏览器数据可能会删除本地会话和资料索引；
- 局域网客户端提交的提示词、图片和检索片段仍会发送到 ShotAI 主机。

“本地”不等于“天然安全”。当前版本没有账号、HTTPS、审计日志、跨浏览器同步、多人任务队列和显存配额，所以只建议放在可信、受控的局域网中，不要把 9090 或模型接口直接暴露到公网。

## 五、Windows 交付不只是把网页打包

ShotAI 同时关注源码运行和 Windows 使用体验。Electron 客户端提供独立窗口、托盘菜单和 9090 服务；关闭窗口后，主机仍可以继续为内网提供服务。安装包默认不包含模型权重，避免安装包和特定模型绑定，也减少分发体积。

项目还保留了 Node 局域网服务和 Windows 精简启动器，分别适合开发、通用内网交付和不同的主机环境。模型、CUDA 运行组件以及大型 DLL 需要由使用者根据自己的设备和模型许可自行准备。

## 六、当前状态与适用范围

我把 ShotAI 定义为 Beta，而不是生产级企业平台。它已经能完成：

- 本地流式对话；
- TXT、Markdown、PDF、DOCX、Excel 等文件阅读；
- 本地资料检索和来源展示；
- 图片理解；
- 本地图片生成与一张参考图的修改；
- GGUF 与视觉模型配套文件检查；
- Windows Electron 客户端和多浏览器访问。

但它暂时不适合公网、多租户、强审计或高并发场景。扫描型 PDF 暂无 OCR，旧版 `.doc` 需要先转换为 `.docx`；多人同时使用时，速度和稳定性取决于主机配置以及模型大小。

如果你的场景是办公室、工作室、家庭或实验室里的一台 GPU 主机服务几台浏览器，ShotAI 可能是一个值得试试的起点。

项目源码和文档：

https://github.com/ReDChicagOTypewriteR/ShotAI

如果你也在设计小团队共享 GPU 的方案，我想交流两个问题：

1. 两到五个用户同时提交任务时，任务队列应该优先按用户、公平性还是任务类型设计？
2. 在 GGUF、视觉模型和 `mmproj` 兼容性上，你最希望工具自动检查什么？

欢迎通过 Issue 分享系统、浏览器、模型和复现步骤。真实的兼容性反馈，比一句“支持所有模型”更有价值。

## 掘金摘要

ShotAI 是一个 Vue 3 + Electron + Ollama 的局域网本地 AI 工作台：一台 Windows 主机运行模型，其他电脑通过浏览器使用对话、文件、资料检索、图片理解和图片创作。本文记录同源代理、任务模型路由、IndexedDB 本地状态和 Windows 交付的工程取舍，并说明当前 Beta 边界。
