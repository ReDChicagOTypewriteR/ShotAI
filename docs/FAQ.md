# 常见问题

## 安装包包含模型吗？

不包含。Windows 和 Ubuntu 完整版包含 ShotAI 与对应平台的模型运行组件，聊天、视觉、Embedding 和图片模型需要单独准备。

## 还需要另外安装 Ollama 吗？

使用 1.2.0 完整安装包时不需要。源码开发或精简部署可以连接外部 Ollama。

## 系统中已有 Ollama，会影响 ShotAI 吗？

1.2.0 完整版默认使用独立端口和模型目录，不读取系统 Ollama 的模型列表。需要复用已有模型时，应在退出 ShotAI 后完整迁移 Ollama 的 `blobs` 和 `manifests`，或重新导入 GGUF。

## 为什么模型导入仍然需要时间？

大文件仍需从源位置读取并写入模型仓库。1.2.0 已取消导入前的完整预扫描，在一次写入中同步校验，并会复用内容相同的文件。机械硬盘、USB 设备、网络挂载和安全软件扫描都会降低速度。

## 模型导入失败后在哪里看原因？

- Windows：ShotAI 数据目录的 `logs`，以及桌面导入错误日志；
- Ubuntu：`~/.config/ShotAI/data/logs/`、桌面 `ShotAI-logs/` 或 `ShotAI-model-import.log`；
- 安装目录可写时，程序也会保存对应运行日志。

## 已删除模型，为什么列表里还存在？

先刷新模型列表并确认删除的是 ShotAI 当前使用的独立模型仓库。系统 Ollama、旧版 ShotAI 和当前完整版本可能使用不同目录。升级后仍异常时，完全退出托盘程序再重新启动。

## 模型回答与问题无关怎么办？

确认当前选择的模型能够正常对话，模型文件与模板来自同一发布版本，并检查是否误选了 Embedding、视觉配套文件或不完整 GGUF。完整版本身不会连接系统 Ollama；如果使用自定义外部服务，应同时检查其地址和模型列表。

## 如何确认实际使用 GPU，而不是回退到 CPU？

完成一次对话后查看 ShotAI 主机监控中的 GPU 推理、显存占用和卸载层数。也可以在主机使用 `nvidia-smi`；仅看到 CUDA 运行库名称不能证明模型已经使用 GPU。

## 五个人可以同时使用吗？

默认最多接纳五条活跃请求，其中两条同时推理、三条排队。第六条请求会提示稍后重试。该策略用于保护显存和上下文稳定性，并不代表五条任务同时在 GPU 上执行。

## Ubuntu 双击 DEB 没反应或进入压缩包怎么办？

在文件所在目录打开终端，执行：

```bash
sudo dpkg -i ShotAI-1.2.0-Ubuntu-22.04-x86_64-Full-Ollama-CUDA.deb
```

完全离线环境不建议依赖软件商店或在线修复命令。

## Ubuntu 可以生成图片吗？

可以。Ubuntu 完整包已内置面向 Ubuntu 22.04 x86_64、CUDA 12 和 NVIDIA V100（sm_70）构建的 `sd-server`，仍需自行导入图片模型。若图片服务无法启动，请查看数据目录 `logs/image-runtime.log`，并确认 NVIDIA 驱动可用。

## 主机监控提示 Method Not Allowed 怎么办？

确认使用当前版本，并从运行 ShotAI 的主机打开监控入口。完全退出旧版托盘进程后重新启动，避免旧服务仍占用端口。监控登录配置保存在数据目录的 `lan.config.json`。

## 本机可以打开，局域网电脑打不开怎么办？

确认局域网电脑访问的是主机当前 IPv4 地址与 `9090` 端口，并检查主机防火墙。不要向其他电脑开放 Ollama 或图片运行组件的内部端口。

## 升级会删除模型和对话吗？

正常覆盖安装默认保留数据目录。对话和部分资料索引保存在各浏览器本地，模型、配置与运行日志保存在主机数据目录。执行手动清理前建议先备份。
